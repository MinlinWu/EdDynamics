# Guide to reproducing the figures and supplementary tables

This index links the manuscript figures and supplementary tables to the original analysis code, supplementary workflows and numerical records.

## Fixed sources

The original public implementation is fixed at [commit aa4a02b5ba980a1c1a81876aa56c1618dded1065](https://github.com/MinlinWu/EdDynamics/tree/aa4a02b5ba980a1c1a81876aa56c1618dded1065). The public scripts use updated report wording for post hoc analyses. For exact checks of an earlier run, match its recorded source hashes to the original files. The supplementary workflows listed below are present in this source tree. To identify the code used for a run, record the checkout’s full commit identifier (`git rev-parse HEAD`) and any local changes alongside the run configuration.

The [source manifest](../supplementary_source_manifest.json) records SHA-256 digests for individual public files and identifies the archived code used for completed experiments. The [numerical source records](Numerical_source_records.md) describe the evidence for the corrected summaries.

Start with [data preparation](../s1_empirical_dynamics/README.md) and follow the [workflow order](../README.md#dependency-order). File and directory names below are relative to the repository root. Each module documents the inputs and commands for its analysis. Prepared inputs, trained checkpoints, predictions and bootstrap draws referenced by downstream commands must be regenerated upstream or supplied from preserved outputs.

Exact replay of the four-term confirmation analysis requires the preserved confirmation-cohort (`B_confirm`) inputs identified by SHA-256 in the [source contract](../s2_minimal_mechanism/robustness/conditional_baselines/source_contract.json), under `b_confirm_coordinate_recovery`. These are the original confirmation panel, the Phase 3 prediction table and seven further bindings, including the Phase 2 freeze and Phase 3 confirmation manifests. New runs can produce different manifest bytes because they record execution times and paths. The nine files are external to this source release. Reuse the matching preserved inputs for a strict replay. The downstream common-reference comparison and the SSL analyses that use the frozen four-term reference also require its completed outputs.

The Methods distinguish the original study design from post hoc analyses, including the additional integrated residence-time and maximum-statistic tests. The comparisons in Supplementary Notes 7–9 were designed after the original study. For the information-removal comparison, five additional paired seeds were selected for evaluation after the representative seed-42 result was available. The [neural analysis design](../s3_event_ssl/robustness/information_controls/README.md#design) distinguishes this six-seed comparison from the 2,000 learner draws conditional on the fixed seed-42 model.

## Corrections from preserved outputs

The [numerical correction record](Numerical_correction_record.json) gives the original and corrected values for 12 residence percentile intervals, the affected pure-SSL summaries, eight six-run retention summaries in Supplementary Table 7 and the interval endpoint in Supplementary Table 11a.

The residence corrections use the saved 1,000 learner draws; the pure-SSL corrections use the six saved original objective-control and geometry evaluations. No retraining, new bootstrap sampling, or outcome selection was performed to obtain these corrections. The eight Table 7 retention summaries use the original scoring functions in [`s3_event_ssl/scripts/extract_event_ssl_random_seed_statistics.py`](../s3_event_ssl/scripts/extract_event_ssl_random_seed_statistics.py) and the six preserved per-seed evaluations. The source records also identify the preserved Parquet used for the Table 11a rounding correction. See the [verification records](Numerical_source_records.md).

For residence intervals, original objective-control summaries and bootstrap diagnostics, the portable report implementation is [`s5_supplementary/scripts/statistical_closure/build_statistical_reports.py`](../s5_supplementary/scripts/statistical_closure/build_statistical_reports.py), documented in that directory's README. Finite-replicate counts, bootstrap displacement and interval-method differences remain part of the reported evidence.
